# 图标系统规范

> 本文件是 UI 图标系统设计的唯一事实来源。应用商店图标规格见 `specs/mobile` 的 M6，本 spec 覆盖产品界面内的功能图标：导航、操作、状态、内容类图标。

## 设计目标

为产品各端产出风格统一、语义清晰、可复用的图标系统。核心矛盾是「一致性」与「灵活性」的平衡--图标系统须统一到用户一眼认出「这是同一套」，但又要足够灵活覆盖各种功能场景。

图标是 UI 中最高频的视觉元素之一。一套混乱的图标系统（线宽不一、风格混用、命名无序）会让界面显得不专业，即使其他设计做得再好。

## 图标分类

| 类别 | 用途 | 示例 |
|------|------|------|
| 操作类 | 表达用户可执行的动作 | 搜索、添加、删除、编辑、分享 |
| 导航类 | 标识页面或位置 | 首页、发现、我的、设置 |
| 状态类 | 表达对象或操作的状态 | 成功、警告、错误、加载中 |
| 内容类 | 表达内容类型或媒介 | 文件、图片、视频、音频、链接 |
| 系统类 | 表达系统级功能 | 返回、关闭、菜单、筛选 |

分类用途：命名前缀与风格选择。同一类内的图标须视觉一致（线宽/填充策略/视角）。

## 操作流程

### IC1. 画布与网格

定义图标的统一画布与网格系统：

- **画布**：24×24px（标准）/ 20×20px（紧凑）。一套图标只用一个画布尺寸
- **安全区**：核心元素内缩 2px（24 画布的活区域为 20×20），避免边缘裁切；**越界判定按实际着墨范围**（路径坐标 + 描边宽度一半 + 圆角端点扩展），不是裸路径坐标——自检扫描须含描边，禁「坐标 ∈ [4,20] 但着墨越界」的假通过
- **关键线**：画布内定义水平/垂直/对角参考线，元素对齐关键线保证视觉重心一致
- **笔画基准**：所有线宽从画布尺寸推导，不用绝对像素

```
24×24 画布：
┌────────────────────────┐
│  ┌──────────────────┐  │  ← 2px 安全区
│  │                  │  │
│  │   核心元素区域     │  │  ← 20×20 活区域
│  │   (对齐关键线)    │  │
│  │                  │  │
│  └──────────────────┘  │
└────────────────────────┘
```

### IC2. 线宽与填充策略

一套图标系统须定义线宽档位与填充纪律：

**线宽档位**

| 档位 | 线宽（24 画布） | 用途 |
|------|---------------|------|
| 细 | 1.5px | 信息密度高的界面、精致风格 |
| 标准 | 2px | 通用，大多数场景 |
| 粗 | 2.5-3px | 需要高识别度、大尺寸场景 |

- 一套图标系统选一个线宽档位，不混用
- 同一视觉层级的图标线宽一致

**填充纪律**

| 策略 | 说明 | 适用 |
|------|------|------|
| 全线框 | 所有图标只用线条 | 精致/极简风格 |
| 全填充 | 所有图标用实心色块 | 活泼/醒目风格 |
| 选中填充 | 默认线框，选中态切填充 | 导航类最常见 |
| 混合 | 不同类别用不同策略 | 不推荐，易乱 |

- 同一层级不混用线框和填充（如导航栏里 3 个线框 2 个填充）
- 选中态切填充是可接受的混合，因为语义不同（选中 vs 未选中）

### IC3. 形状语言

定义图标的形状规则，保证视觉统一：

- **圆角**：端点圆角与转角圆角统一（如全部 round 端点 + round 转角）
- **端点**：线段端点统一为 round（不用 butt 或 square，除非刻意做硬朗风格）
- **转角**：内转角与外转角统一（如全部 2px 圆角）
- **对称性**：可对称的图标须严格对称（如搜索图标左右对称）
- **比例**：同类元素的尺寸比例统一（如所有图标中的「圆」大小一致）

### IC4. 语义与命名

命名遵循 `ic_<类别>_<名称>.svg` 格式：

| 命名 | 类别 | 示例 |
|------|------|------|
| ic_action_* | 操作类 | ic_action_search.svg、ic_action_delete.svg |
| ic_nav_* | 导航类 | ic_nav_home.svg、ic_nav_profile.svg |
| ic_status_* | 状态类 | ic_status_success.svg、ic_status_error.svg |
| ic_content_* | 内容类 | ic_content_file.svg、ic_content_image.svg |
| ic_system_* | 系统类 | ic_system_back.svg、ic_system_close.svg |

- 名称用英文 snake_case，不用中文拼音
- 同一语义只有一个图标（如「删除」只用 ic_action_delete，不另造 ic_action_remove）
- 变体用后缀：`_filled`（填充）、`_outline`（线框）、`_disabled`（禁用态）

### IC5. 状态变体

导航类和操作类图标须有状态变体：

| 状态 | 视觉变化 | 实现方式 |
|------|---------|---------|
| 默认 | 线框，中性色 | 基础图标 |
| 选中 | 填充，主色 | `_filled` 变体或 `currentColor` 切换 |
| 禁用 | 线框，低透明度 | opacity 降低或用 disabled 色 |
| 悬停 | 线框，加深色 | `currentColor` 加深 |
| 按压 | 线框，主色 | 同选中态或加深 |

- 状态切换用 `currentColor` + CSS/主题色，不每态画一个图标
- 选中态切填充时，填充版本与线框版本须形状一致（只变填充方式，不改形）

### IC6. 尺寸使用

图标在 UI 中的使用尺寸须有档位，不随意：

| 档位 | 尺寸 | 用途 |
|------|------|------|
| sm | 16×16px | 行内图标、标签前缀、密集列表 |
| md | 20×20px | 按钮、表单、卡片 |
| lg | 24×24px | 导航栏、工具栏 |
| xl | 32×32px | 空状态插画、大按钮 |

- 使用尺寸从画布等比缩放，不拉伸变形
- 触控目标不够时扩大命中区（hitSlop），不放大图标

### IC7. 导出

**可审阅图标集 HTML**（首选）：单页 HTML，将整套图标网格展示供一致性审阅

- 按类别分组（操作/导航/状态/内容/系统），每类一个区块
- 每图标一格：图标预览 + 名称 + 线宽 + 状态变体（默认/选中/禁用）
- 弹出式审阅（见 `specs/review`）：每图标格有 [+] 按钮，点击弹窗写反馈 + 快捷标记
- 支持导出 Markdown/JSON 给 AI 修改，保留上一轮反馈对比
- 用于独立图标系统任务或项目流程中的图标审阅检查点

图标集的设计原则跨端共用（画布/线宽/分类/命名/状态），但实现方式各端差异大。各端实现细节见平台深潜 spec：

| 平台 | 深潜 spec | 何时读取 |
|------|----------|---------|
| Web | `specs/icon-system/web.md` | 目标含 Web 时 |
| iOS | `specs/icon-system/ios.md` | 目标含 iOS 时 |
| Android | `specs/icon-system/android.md` | 目标含 Android 时 |
| 鸿蒙 | `specs/icon-system/harmony.md` | 目标含鸿蒙 时 |

多端时按需并行读取。通用导出约束：

- SVG 须：无外部依赖、路径转曲（outline）、`fill="currentColor"` 或 `stroke="currentColor"`
- 一个文件一个图标，不合并
- 按类别建目录：`assets/icons/action/`、`assets/icons/nav/` 等
- 各端具体的文件格式、资源目录、命名后缀见对应平台深潜

图标集 HTML 定稿后导出正式 SVG/资源文件。

## 验收标准

- [ ] 一套图标只用一个画布尺寸（24 或 20）
- [ ] 安全区 2px，核心元素不超出
- [ ] 线宽统一（一个档位贯穿全系统）
- [ ] 端点与转角圆角统一
- [ ] 同一层级不混用线框和填充
- [ ] 选中态切填充时形状一致
- [ ] 命名遵循 `ic_<类别>_<名称>` 规范
- [ ] 同一语义只有一个图标
- [ ] 导航/操作类有状态变体（默认/选中/禁用）
- [ ] 使用尺寸有档位（sm/md/lg/xl），不随意
- [ ] SVG 无外部依赖、转曲、支持 currentColor
- [ ] 按类别建目录

## 边界与不做项

- 应用商店图标规格见 `specs/mobile` 的 M6（那是 App 图标，不是 UI 图标）
- 品牌 Logo 设计见 `specs/brand` 的 B2（Logo 不是图标系统的成员）
- 插画系统见 `specs/illustration`（插画是多元素组合，图标是单元素符号）
- Token 架构见 `specs/design-system`（图标尺寸作为 Token 管理如 icon-sm/icon-md）
- 图标尺寸触控目标要求见各端 spec（`specs/mobile`、`specs/web`）
- 各端图标实现细节见 `specs/icon-system/web.md`、`ios.md`、`android.md`、`harmony.md`，本文件仅定义跨端设计基线
