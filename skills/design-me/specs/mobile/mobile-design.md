# 移动端设计规范

> 本文件是移动端（iOS/Android/鸿蒙）设计的唯一事实来源。所有移动端产出须通过文末验收清单。

## 设计目标

为移动设备产出符合各平台人机界面指南的界面，并产出可直接用于工程集成的启动图、图标与切图资源。核心矛盾是「平台原生体验」与「跨端品牌一致性」的平衡--尊重平台惯例，但不牺牲品牌识别。

三平台各有独立设计语言，不可一套稿通吃：

| 平台 | 设计语言 | 导航惯例 | 触控单位 |
|------|---------|---------|---------|
| iOS | Apple HIG | 底部 Tab Bar | 44×44pt |
| Android | Material Design | 顶部 App Bar + 抽屉 | 48×48dp |
| 鸿蒙 | HarmonyOS UX | 分布式服务卡片 | 遵循鸿蒙规范 |

三平台各有独立设计语言与深潜规范。本文件定义跨端共用的操作流程与验收底线；各平台具体设计语言、控件体系、资源规格见下表：

| 平台 | 深潜 spec | 何时读取 |
|------|----------|---------|
| iOS | `specs/mobile/ios.md` | 目标平台含 iOS 时 |
| Android | `specs/mobile/android.md` | 目标平台含 Android 时 |
| 鸿蒙 | `specs/mobile/harmony.md` | 目标平台含鸿蒙时 |

多端项目时三个文件按需并行读取，以 `specs/brand` 为一致性锚点。

## 操作流程

### M1. 平台适配解构

确定目标平台（可多选），并读取对应的平台深潜 spec：

- iOS -> 读 `specs/mobile/ios.md`（Apple HIG：Tab Bar、Dynamic Type、Sheet detents、SF Symbols）
- Android -> 读 `specs/mobile/android.md`（Material 3：State Layers、Type Roles、Adaptive、Predictive Back）
- 鸿蒙 -> 读 `specs/mobile/harmony.md`（HarmonyOS UX：一多自适应、分布式流转、服务卡片）

多平台时先定品牌基线（见 `specs/brand`），再按各平台深潜 spec 差异化：

- 导航结构各平台不同（iOS Tab Bar vs Android Top App Bar）
- 控件风格各平台不同（iOS 圆角实体 vs Material 涟漪状态层）
- 字体系统各平台不同（iOS Dynamic Type vs Material Type Roles）
- 同一品牌色在各平台可微调饱和度以适应平台渲染

### M2. 安全区与屏幕适配

- 顶部：状态栏 / 刘海 / 灵动岛
- 底部：手势条 / Home Indicator
- 侧边：曲面屏边缘
- 固定栏（顶栏/底栏/CTA 栏）须避开安全区
- 滚动内容须为固定栏预留 inset，不被遮挡

```
安全区示意：
┌─────────────────┐
│   状态栏/刘海    │  <- 顶部安全区
├─────────────────┤
│                 │
│    可交互内容    │
│                 │
├─────────────────┤
│   手势条区域     │  <- 底部安全区
└─────────────────┘
```

### M3. 触控与手势

- 触控目标 ≥ 44×44pt（iOS）/ 48×48dp（Android），图标小于此值时用 hitSlop 扩大命中区
- 触控目标间距 ≥ 8pt
- 不依赖 hover（移动端无 hover），主交互用点击/轻触
- 不阻挡系统手势（控制中心、返回滑动）
- **演示页交互真实性**：页内声明的交互必须有实现——onclick 引用的函数未定义 = 死交互；文案宣称的确认/toast 无载体 = 摆拍（可脚本化）
- **平台图形资产不摆拍**：状态栏/系统图形用 inline SVG 渲染，禁 SF Symbols 私有区码点（浏览器内为豆腐块，仅真机可用且须显式标注）
- 按压反馈 100ms 内出现（涟漪/透明度/阴影），动效 Token 见 `specs/motion`
- 使用平台标准手势（返回滑动、双指缩放），不重定义
- 不要求像素级精准点击小图标或薄边缘
- 提供触觉反馈用于确认与重要操作，不过度

### M4. 导航模式

- 底部导航 ≤ 5 项，图标 + 文字标签（禁纯图标导航）
- 抽屉/侧栏用于二级导航，不用于主操作
- 返回行为可预测且一致，保留滚动与状态
- 关键页面须可深度链接到达
- 当前位置须视觉高亮（颜色/字重/指示器）
- 模态须有明确关闭入口，移动端支持下拉关闭
- 禁在同一层级混用 Tab + 侧栏 + 底部导航
- 模态不用于主导航流程（会打断用户路径）

### M5. 启动图设计

基于 App 截图或品牌元素生成各平台启动图：

| 平台 | 必需尺寸 | 要点 |
|------|---------|------|
| iOS | 640×1136 / 750×1334 / 1125×2436 / 2048×2732 等 | 支持 Launch Screen Storyboard |
| Android | 多密度 splash 资源 | 用 SplashScreen API 或主题背景图，防拉伸 |
| 鸿蒙 | 按华为应用市场与系统要求 | 支持刘海/挖孔安全区 |

约束：

- 背景非纯白/纯黑，须传达品牌识别（否则被商店驳回）
- 简洁高级，不大段文字
- 遵守 Apple HIG / Material / 鸿蒙 UX 对启动图的要求
- 不用未授权素材，不误导为系统界面

### M6. 图标规格

基于主 Logo/图标，生成各平台完整图标集：

| 平台 | 规格 |
|------|------|
| Web | favicon.ico (16/32/48)、apple-touch-icon (180)、mstile (150) |
| iOS | 1024×1024 主文件 + 20pt/29pt/40pt/60pt/76pt/83.5pt 各 1x/2x/3x PNG |
| Android | 自适应图标前/背景层 (108×108dp -> 432×432px) + mdpi-xxxhdpi 全密度 |
| 鸿蒙 | 启动图标 (162×162px) + 分层前景背景 |

约束：

- SVG 须标准规范、无外部字体依赖、转曲
- 图标设计考虑安全区，核心元素不被裁切
- 文件命名遵循平台规范（如 `ic_home@2x.png`、`bg_login@3x.png`）

### M7. 切图与资源

对设计稿元素 1:1 像素级切片：

- 自动识别图标、按钮、背景、分割线
- 切片尺寸与设计稿占用像素精确对应
- 输出 SVG + @1x/@2x/@3x PNG
- 多状态图（normal/hover/pressed）
- 文件夹结构：`assets/icon/` `assets/bg/` `assets/image/` 分密度目录
- 可选 style.json（颜色、文本样式 Token）
- 命名兼容 Win/macOS/Linux 文件系统，无特殊字符

## 验收标准

- [ ] 触控目标 ≥ 44pt（iOS）/ 48dp（Android），间距 ≥ 8pt
- [ ] 固定栏避开安全区，滚动内容不被遮挡
- [ ] 按压反馈 100ms 内出现
- [ ] 底部导航 ≤ 5 项，图标 + 文字
- [ ] 返回行为可预测，状态与滚动保留
- [ ] 启动图背景非纯色，符合各平台人机规范
- [ ] 图标集覆盖所有必需尺寸与密度；**回归/clean-room 场景达标形态 = 矢量主文件 + 分层源（Android fg/bg/mono）+ 尺寸密度清单表**，位图全密度由构建管线栅格化，禁在无管线环境硬凑或虚勾
- [ ] 切图尺寸与设计稿 1:1 对应，误差为 0；无设计稿切片任务时标 `N/A（<原因>）`，禁硬勾
- [ ] 文件命名遵循平台规范，无特殊字符
- [ ] 暗色模式独立验证通过
- [ ] 触觉反馈用于确认/重要操作，未过度
- [ ] 不阻挡系统手势
- [ ] 页内声明交互均有实现（onclick 函数有定义、宣称的 toast/确认有载体）；系统图形非私有区码点

## 边界与不做项

- 不负责后端接口与数据结构
- 不负责应用上架审核流程本身（但产出须符合审核要求）
- Web 端响应式布局见 `specs/web`
- 品牌视觉基线（Logo、色彩、字体）见 `specs/brand`
- iOS 平台深潜（Apple HIG）见 `specs/mobile/ios.md`
- Android 平台深潜（Material 3）见 `specs/mobile/android.md`
- 鸿蒙平台深潜（HarmonyOS UX）见 `specs/mobile/harmony.md`
- 切图后的代码集成由开发负责，本规范止于资源交付
