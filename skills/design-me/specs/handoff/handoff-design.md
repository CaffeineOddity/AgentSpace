# 设计交付规范

> 本文件是设计到开发交付流程的唯一事实来源。各端 spec 定义设计规范，本 spec 定义如何把设计稿变成开发可直接使用的交付物。

## 设计目标

让设计稿从「好看」变成「好做」--交付物须让开发无需猜测间距、字号、颜色值，直接按标注实现。核心是**零偏差还原**：设计稿与最终上线产出的像素级误差趋近于零。

交付质量低导致两个后果：开发反复猜测猜测导致还原偏差；设计反复走查指出偏差导致返工。好的交付物在源头消除这两条。

## 交付物清单

| 交付物 | 内容 | 消费方 |
|--------|------|--------|
| 设计稿 | 高保真页面/组件预览图 | 设计走查、评审 |
| 标注文档 | 间距/字号/颜色/圆角/阴影标注 | 开发实现 |
| 资源包 | 切图/图标/插画素材 | 开发集成 |
| Token 文件 | style.json / 各端主题配置 | 开发主题配置 |
| 交互说明 | 状态/动效/边界条件 | 开发行为实现 |
| 走查清单 | 验收标准逐项 | 设计 QA |

## 操作流程

### H1. 标注规范

设计稿须标注以下维度，开发按标注实现：

| 维度 | 标注内容 | 单位 |
|------|---------|------|
| 间距 | 元素间 padding/margin | px / dp / pt |
| 尺寸 | 元素 width/height | px / dp / pt |
| 字号 | font-size / line-height | px / sp / pt |
| 字重 | font-weight | 400/500/600/700 |
| 颜色 | 语义名 + hex | 语义名优先 |
| 圆角 | border-radius | px / dp / pt |
| 阴影 | shadow（x/y/blur/opacity） | 各端格式 |
| 层级 | z-index | 数字 |

标注原则：

- 间距标注从基准线开始（如从卡片内边缘到内容），不从屏幕边缘
- 颜色标注用语义名（`color-primary`）+ hex（`#FF6B35`），不用裸 hex
- 字号标注含字重和行高（如 `16px / 500 / 1.5`）
- 标注不遮挡设计稿内容，用引线指向
- **按元素类型裁剪标注表**：静态展示元素无 z-index/阴影时该格留「-」即可，不为凑满 8 列造标注；标注密度服从「开发无需猜测」这个目标，不服从「表格填满」

### H2. 状态与交互说明

设计稿须覆盖所有交互状态，不能只画 default 态。**按元素类型取适用状态**，不硬套全表：控件级元素（按钮/输入框/开关）须覆盖全状态表；容器/展示级元素（卡片/图片/静态区块）通常只需 default + hover（Web），没有 loading/error/empty 就不造状态，在走查清单注明「该元素 N/A」即可：

| 状态 | 说明 |
|------|------|
| default | 默认态 |
| hover | 鼠标悬停（Web） |
| focus | 键盘/触控聚焦 |
| active/pressed | 按下 |
| disabled | 禁用 |
| loading | 加载中 |
| error | 错误态 |
| empty | 空数据 |
| success | 操作成功 |

每个状态须有：视觉变化说明 + 触发条件 + 恢复条件。

交互动效说明引用 `specs/motion` 的 Token，标注时长 + 缓动 + 属性（如 `duration-normal / easing-enter / property-scale`）。

### H3. 资源导出

切图与素材导出遵循 `specs/mobile` 的 M7 切图与资源规范，并补充：

| 资源类型 | 格式 | 命名 | 密度 |
|---------|------|------|------|
| 图标 | SVG + PNG | `ic_<name>.svg` / `ic_<name>@2x.png` | @1x/@2x/@3x |
| 背景图 | PNG/WebP | `bg_<name>@2x.png` | 按端 |
| 插画 | SVG/Lottie | `ill_<scene>.svg` / `ill_<scene>.json` | 矢量优先 |
| 品牌图 | SVG/PNG | 按品牌规范 | 多尺寸 |

- 矢量优先（SVG/Lottie），位图按需补密度
- 切图尺寸与设计稿占用像素 1:1 对应，误差为 0
- 文件名兼容 Win/macOS/Linux，无特殊字符/空格/中文

### H4. Token 交付

Token 文件是设计到代码的契约，引用 `specs/design-system` 的 Token 架构：

```json
{
  "color": { "primary": "#FF6B35", "on-primary": "#FFFFFF", ... },
  "font":  { "display": "Poppins", "body": "Inter", ... },
  "space": { "1": 4, "2": 8, "3": 12, ... },
  "radius": { "sm": 4, "md": 8, "lg": 16 },
  "shadow": { "sm": "0 1px 2px ...", "md": "0 4px 8px ..." },
  "motion": { "duration-fast": "150ms", "easing-enter": "..." }
}
```

- Token 为单一源，各端按需导出（CSS 变量 / Swift 主题 / XML 主题）
- 开发消费 Token，不自行定义颜色/字号/间距值
- 改 Token = 改设计，二者同步（SDD）

### H5. 边界条件说明

设计稿须注明以下边界条件，否则开发会自行猜测导致偏差：

| 条件 | 说明 |
|------|------|
| 文字超长 | 截断（省略号）/ 换行 / 缩小，哪种策略 |
| 数据为空 | 空状态插画（见 `specs/illustration`） |
| 数据极多 | 列表虚拟化 / 分页 / 折叠 |
| 网络异常 | 错误页 + 重试入口 |
| 权限不足 | 无权限提示 + 申请入口 |
| 极端尺寸 | 最小屏 / 最大屏 / 横屏布局 |
| 暗色模式 | 各元素的暗色变体 |

### H6. 走查清单

设计交付前须按走查清单自检，走查清单是该端 spec 的验收标准 + 以下交付专属项：

- [ ] 标注覆盖所有间距/尺寸/字号/颜色/圆角/阴影（按元素类型裁剪，不适用的维度留「-」而非造值）
- [ ] 颜色用语义名 + hex，无裸 hex
- [ ] 所有交互状态已画（控件级元素全状态表；容器/展示级元素 default+hover 并注明 N/A 项）
- [ ] 动效标注引用 `specs/motion` Token
- [ ] 切图尺寸与设计稿 1:1，误差为 0
- [ ] 矢量资源优先（SVG/Lottie）
- [ ] 文件命名规范，无特殊字符
- [ ] Token 文件已交付，开发可直接消费
- [ ] 边界条件已注明（超长/空/极多/异常/权限/极端尺寸/暗色）
- [ ] 边界条件中声明的响应式断点行为须有对应 `@media` 实现锚点（交付标注写了行为而无实现 = 声明与实现脱节，照标注还原将与实际组件不符）
- [ ] 该端 spec 的验收清单全部通过

## 边界与不做项

- 不定义设计规范本身（各端 spec 负责）
- 不定义 Token 架构（见 `specs/design-system`）
- 不定义动效原则（见 `specs/motion`）
- 不定义插画风格（见 `specs/illustration`）
- 切图/图标的平台规格见 `specs/mobile`
- 代码实现由开发负责，本规范止于交付物
