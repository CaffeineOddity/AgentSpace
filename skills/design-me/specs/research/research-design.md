# 设计研究规范

> 本文件是设计研究与竞品分析的唯一事实来源。设计研究是设计流程的「Phase 0」--在页面描述（`specs/workflow` Phase 1）之前，先理解问题空间、竞品解法与用户场景。

## 设计目标

在动手设计之前，系统性地理解要解决的问题。核心矛盾是「研究深度」与「推进速度」的平衡--不研究直接设计容易拍脑袋，过度研究容易分析瘫痪。目标是用最小成本获取「足够做对设计决策」的研究输入。

设计研究解决三个问题：**竞品怎么解的**（避免重复造轮子或低于行业基线）、**行业模式是什么**（提取可复用的设计模式）、**用户场景在哪**（设计服务于真实使用场景，非假想）。

## 研究范围

| 研究维度 | 回答什么 | 产出 |
|---------|---------|------|
| 竞品分析 | 同类产品怎么解这个问题 | 竞品对比矩阵 |
| 设计模式提取 | 行业里有哪些成熟的设计模式 | 模式清单 + 适用场景 |
| 用户场景 | 用户在什么场景下用这个功能 | 场景故事 + 关键约束 |
| 视觉参考 | 行业视觉趋势、风格参考 | moodboard（情绪板） |

## 操作流程

### R1. 确定研究范围

从 PRD 或用户需求中提取要研究的问题：

- 要设计什么功能/页面/产品？
- 它属于什么品类（工具/社交/电商/内容/生产力）？
- 目标用户是谁？使用场景是什么？

不贪多：一次研究聚焦一个功能域或一个品类，不做全产品扫描。

### R2. 竞品选取

选取 3-5 个竞品，按角色分层：

| 层级 | 选取标准 | 数量 |
|------|---------|------|
| 直接竞品 | 同品类、同目标用户 | 2-3 个 |
| 间接竞品 | 不同品类但解同类问题 | 1 个 |
| 标杆产品 | 该领域公认最佳实践 | 1 个 |

- 直接竞品看「同行怎么做」
- 间接竞品看「跨行业有没有更好的解法」
- 标杆看「上限在哪」
- **每层须有真实落点**：同产品可兼任相邻层（如直接兼标杆），但兼任不得让某一层整个缺席——「2 直接 + 1 间接兼标杆」若全文无任何间接竞品，是凑层不是覆盖；找不到跨品类解法时如实写「间接层暂缺及原因」，不虚标

竞品不贪多：3-5 个足够提取模式，超过 5 个边际收益递减。

- **3 个竞品满足「直接/间接/标杆」三层的合法方式**：3 个产品中 2 直接 1 间接，标杆可直接标注在最强直接竞品上（同产品可兼任直接与标杆），不必凑 4 个产品

### R3. 竞品分析

对每个竞品，按以下维度拆解：

**功能层**
- 核心流程是什么（用户从进入到完成目标经过几步）
- 关键功能点有哪些
- 信息架构怎么组织的（导航层级、分类逻辑）

**交互层**
- 核心操作用什么交互模式（如搜索用即时搜索还是按钮触发）
- 状态设计是否完整（加载/空/错误/成功怎么处理）
- 有没有值得学习的微交互

**视觉层**
- 整体风格方向（极简/丰富/专业/活泼）
- 色彩策略（主色占比、对比度、暗色模式）
- 字体配对（展示字体 + 正文字体）
- 图标/插画风格

**差异化**
- 这个竞品做对了什么（值得借鉴）
- 做错了什么（避免踩坑）
- 有什么是独有的（不抄但要知道）

### R4. 模式提取

从竞品分析中提取可复用的设计模式，不是为了抄，是为了知道「行业常见解法」：

| 模式类型 | 示例 |
|---------|------|
| 导航模式 | 底部 Tab / 侧栏 / 顶部 Tab / 抽屉 |
| 搜索模式 | 即时搜索 / 按钮触发 / 语音输入 |
| 列表模式 | 无限滚动 / 分页 / 卡片流 / 表格 |
| 表单模式 | 单页 / 分步 / 手风琴 / 行内编辑 |
| 反馈模式 | Toast / Snackbar / 模态 / 行内提示 |
| 空状态模式 | 插画 + 文案 + 行动按钮 / 纯文案 |

每个模式记录：
- 是什么（一句话描述）
- 适用场景（什么条件下用）
- 竞品谁在用（来源标注）
- 优缺点

### R5. 用户场景

构建 1-2 个真实使用场景故事，回答：

- 用户在什么环境下用（通勤/办公/休闲）
- 用什么设备（手机/桌面/平板）
- 用户的目标是什么（要完成什么任务）
- 有什么约束（时间紧/网络差/干扰多）
- 当前流程的痛点是什么

场景故事不是 persona（虚构人物画像），是具体到「一个真实场景下的使用路径」。它帮设计师判断：这个设计在真实场景下是否可用。

### R6. moodboard（情绪板）

收集视觉参考，建立风格方向共识：

- 从竞品中提取视觉亮点（截图 + 标注）
- 从非竞品中找风格参考（如 Dribbble/Behance/Pinterest 的相关作品）
- 按「色彩/字体/排版/图标/插画/摄影」分类整理
- 提取 3-5 个关键词描述目标风格（如「温暖、柔和、可信赖」）；**每个关键词带一句操作性解释与落点**（如「沉浸=书写界面单栏无边栏，行宽收窄」），裸词列无法被 Phase 1 操作化；本步可以文字方向先行，但竞品视觉亮点与非竞品参考须补齐后才算 moodboard 定稿

moodboard 的用途是与用户/团队对齐风格方向，不是直接拿来做设计。它降低「方向未确认就开干」的返工风险。

### R7. 研究综合

将以上产出综合为一份研究摘要，结构：

1. **问题定义**：要解决什么设计问题
2. **竞品洞察**：行业怎么解的，最佳实践是什么
3. **模式清单**：可复用的设计模式及适用场景
4. **用户场景**：真实使用路径与约束
5. **风格方向**：moodboard + 风格关键词
6. **设计建议**：基于研究，建议的设计方向（非最终方案）

研究摘要的读者是后续设计流程（Phase 1 页面描述 -> Phase 2 低保真），不是用户。它是设计内部的输入文档。

摘要头部附**研究元信息**：研究方法、竞品版本/时间、事实性断言的可核性说明（走查观察 vs 定量结论）、研究日期——后续 Phase 引用断言时可判断置信度。

## 与设计流程的关系

设计研究是 `specs/workflow` Phase 1 之前的「Phase 0」：

```
Phase 0 · 设计研究（本 spec）-> 研究摘要
    ↓ 输入
Phase 1 · 页面描述 -> 每页 design/output/pages/<页面ID>.md（功能定位/进出/状态/布局结构）
    ↓ 输入
Phase 2 · 低保真 -> 线框
```

研究摘要中的模式清单直接影响 Phase 1 的页面结构与布局选择（如用底部 Tab 还是侧栏），moodboard 的风格方向影响 Phase 3 的 IP 与品牌基线。

## 验收标准

- [ ] 竞品选取 3-5 个，含直接/间接/标杆三层
- [ ] 每个竞品按功能/交互/视觉/差异化四维度分析
- [ ] 提取 ≥ 5 个可复用设计模式，每个有适用场景标注
- [ ] 构建 1-2 个用户场景故事，含环境/设备/目标/约束/痛点
- [ ] moodboard 按 6 个维度（色彩/字体/排版/图标/插画/摄影）分类
- [ ] 提取 3-5 个风格关键词
- [ ] 研究摘要含 6 个部分（问题定义/竞品洞察/模式清单/场景/风格/建议）
- [ ] 研究摘要的建议方向有竞品或场景依据，非主观偏好

## 边界与不做项

- 不负责 PRD 撰写（研究从 PRD 或需求开始）
- 不负责定量用户调研（问卷/数据分析非本 spec 范围，但研究摘要可引用其结论）
- 不负责最终设计方案（研究产出是方向建议，设计执行见 workflow 各 Phase）
- 竞品分析不等于抄袭--提取模式是为知道行业基线，不是复制竞品界面
- 品牌视觉基线定义见 `specs/brand`，moodboard 是方向参考不是品牌 spec
