# 专业设计师高保真 UI 的验收方法与工作纪律

> 供 design-me Phase 4 高保真阶段对齐使用：反 AI slop 明细、排印与可读性底线、form 推导五问（从内容长设计）、5 维度专业评审（Keep / Fix / Quick Wins）、Playwright 验证方法、工作纪律。与 `design-workflow.md` Phase 4「步骤 4.2 动态质感质量闸门」互相补充、不冲突。

## 1. 验证方法（Playwright 截图 / 控制台 / 人工验收）

- 必须用真实渲染器验收，缩略图（`qlmanage -t`）不是渲染，绝不当验收依据。
- 必须先验证验证工具本身可信：把一个「已知正确的同类页」喂给同一渲染器做对照实验，工具不渲染中文/漏内容即判定环境问题、不是产物问题（macOS 上 LibreOffice headless 渲染中文会整体丢失）。
- 必须用 Playwright headless chromium 打开每个高保真 HTML：截图到项目目录 + 抓取控制台错误。
- 必须要求控制台 `pageerror` 为 0（JS 报错是白屏主因，非 0 不交付），App/iOS 原型交付前同理跑点击测试 `pageerror` 为 0。
- 必须交付前自己肉眼过一遍浏览器，且打开真实浏览器（`--show` / headless=false）看交互效果，不只信静态截图；这次肉眼是最后一道「第二双眼」闸门。
- 必须做多 viewport 截图：`1920x1080,1440x900,768x1024,375x667`（Web/App 各端范围按目标设备选），宽屏/窄屏各有截图，响应式页三档都验。**按产物形态选档**：响应式 Web 页三档全验；固定画布 App 原型验目标设备尺寸 + 一档宽屏（确认容器居中不破即可，不按响应式标准要求）。
- 必须按页面逐一截图（每页一图，Deck 类逐页截），如实呈现交付形态，不是只截首屏。
- 必须等待动画 settle 再截图（`page.wait_for_timeout(2000)`），防止截到中间态；动画优先 `transform`/`opacity`（GPU 加速），卡顿用 DevTools Performance 找 layout thrashing。
- 必须用 `device_scale_factor=2` 出 retina 高清截图，避免糊片掩盖像素级问题。
- 关键流程点击测试项（App/iOS 必跑 3 项）：进详情页 / 关键标注点（或重点交互） / tab 切换，外加 modal 开关、表单提交、返回出口各点一遍。
- 「看起来对但 interaction 有 bug」「静态好看但 scroll 错位」「Tweaks 切换后组件不响应」都是 AI 高发坑，列入人工过浏览器时必查清单。
- 交互类交付（可点击/可切换/可变体）建议让用户自己开浏览器点一遍，作者截图覆盖不到交互流。

## 2. 专业评审维度（5 维度 + 优先级 + 输出结构）

- 区分「概念/立意」为首位（权重最高），排在 5 维度之前单独把关：执行是放大镜，放大空洞的概念只会更空洞。
- 必须检查「概念/立意」：这个设计有没有一个 idea、能用一句话讲出来；讲不出来 = 没有。
- 必须做盖logo测试：盖住所有文字和 logo 还认得出主题吗？认不出 = 视觉没承担表达（纯文字排版除外，改问「换主题这套文字处理还成立吗」）。
- 必须做换皮测试：换个客户名/产品名还成立吗？成立 = 模板套皮，概念维直接 ≤5 分。
- 必须执行一票否决：概念 ≤5 分时总评封顶 6.0（良好档下限），先修概念再谈执行，execution 救不回没 idea 的设计。
- 5 维度之一「哲学一致性」：是否用了选定哲学的标志性手法、色彩/字体/布局是否符合该体系、有无自相矛盾元素（如选了极简哲学却塞满内容）。
- 5 维度之二「视觉层级」：眯眼测试仍清晰、标题/正文字号差至少 2.5 倍、颜色粗细能建立 3-4 个层级、留白引导视线。
- 5 维度之三「细节执行」：统一的间距系统（8px 网格）、同类元素间距一致、颜色 ≤3-4 种、字体 ≤2 种、边缘对齐精确。
- 5 维度之四「功能性」：删掉任一元素设计会不会变差？不会就删；CTA/关键信息在最显眼位；警惕「因为好看所以加上去」的元素；信息密度与载体匹配。
- 5 维度之五「创新性」：避开常见 cliché（渐变圆球代表 AI、数字雨、蓝色电路板、机器人脸、`#0D1117`+霓虹 glow 等），在哲学框架内有个人表达、「意想不到但合理」的决策。
- 必须输出标准结构：总体评分 + 分项评分 + **Keep**（做得好的，用设计语言描述）+ **Fix**（按严重程度排，标 ⚠️致命/⚡重要/💡优化，每条含「当前/问题/修复含数值」）+ **Quick Wins**（只有 5 分钟时优先做的 3 件事，打勾清单）。
- 必须「评审设计不评设计师」，Findings 指向设计决策，不评人与动机。
- 区分评审侧重：App UI 以功能性/细节执行为主、视觉层级次之、哲学一致性可放宽（可用性优先）；落地页四维全面要求。

## 3. form 推导五问（从内容长设计）

每个页面/屏幕开工前必答「form 推导五问」，五问答完再 vocalize 设计系统（色彩/字型/layout/组件）——系统服务于答案，不是先选系统再塞内容：

- 叙事角色：这一屏是 hero / 过渡 / 数据 / 引语 / 结尾？（一页内每屏都可能不同）。
- 观众距离：10cm 手机 / 1m 笔记本 / 10m 投屏？（决定字号与信息密度）。
- 视觉温度：安静 / 兴奋 / 冷静 / 权威 / 温柔 / 悲伤？（决定配色与节奏）。
- 容量估算：用纸笔画 3 个 5 秒草图算内容塞不塞得下（防溢出/防挤压，别等渲染后才发现文本框爆）。
- 视觉母题：这个内容独有的视觉母题是什么？从内容里找一个别的主题不会有的视觉元素/结构/隐喻，作为 form 的种子——母题是「设计从内容长出来」的最小证据，答不出 = 还在靠风格标签抽签。
- 检查点：五问答案 + 系统「口头说出来等用户点头」再写代码，方向错了晚改比早改贵 100 倍。
- 交付要求：每版交付时写一句「form 来自内容的哪里」，写不出来 = 在套模板，回去重答第五问（视觉母题）。

## 4. 五问对 UI 页面/屏幕的改写（网页/App 原型，非 deck/镜头）

- 把「镜头/页」改成「页面/屏幕」：叙事角色 = 这屏在流程中的角色，取「入口屏/主内容屏/数据屏/表单屏/确认或结果屏/引导屏」等 App/Web 语义，替代 hero/过渡 等 deck 语。
- 叙事角色改写：hero → 首页首屏（价值主张落点）；数据 → 仪表盘/列表/详情的数据区；引语 → 引用块/用户实证/空态文案区；结尾 → 结果/成功/收尾屏；过渡 → 加载/转场/中间态屏。
- 观众距离改写（按屏类型取舍）：首屏要 1m 抓注意力（大标题、明确 anchor）；列表/表单/详情正文默认近距舒适字号；不是每屏都按手机 10cm 压信息密度——按「这屏用户离多远、干什么」定。
- 视觉温度改写：不是整片一个调，而是按「情绪关键屏」定温度峰值（激活屏 vs 安静表单屏可比），并把五问温度落到配色/节奏 Token。
- 容量估算改写：把「3 个 5 秒 thumbnail」换成「按页面描述文档的布局结构与各状态」做容量估算——默认态/加载/空/错误都塞得下才合格，防高保真阶段才爆文本/溢出。
- 视觉母题改写：从**本产品的内容与数据**里找别的产品不会有的视觉元素/结构/隐喻（IP 形象、领域特有结构、主名词），作为本屏 form 种子；不要从风格库/组件库抽。
- form 来自内容的哪里（UI 一句自证）：指认「这个母题出自本产品哪份真实内容，换成别家产品不成立」，能指认出 = 没套模板；指认不出 = 回去重答第五问。

## 5. 工作纪律

- 必须从 existing context 出发，不凭空画：先问/找 design system、UI kit、codebase、Figma、截图、品牌资产；凭空做 hi-fi 是 last resort，必然产出 generic。
- 事实优先于假设：涉及具体产品/技术/规格的事实性断言，第一步 WebSearch 验证，不凭训练语料；事实写进 `product-facts.md`，不靠记忆。
- 涉及真实品牌/产品名时，铁律取官方 logo 与真实产品图（资产 > 规范），不用 SVG 手画/CSS 剪影冒充真实产品图；Design-me 已有品牌/IP/Token 时继承之，不重新发明。
- 必须 placeholder 真诚：没数据就写真实占位注释（「等用户提供真实数据」）留诚实占位，不编造看起来像数据的假数字；hi-fi 里一个诚实 placeholder 比拙劣真实尝试好 10 倍。
- 必须反填充（系统优先，Don't add filler）：每个元素都要 earn its place，用构图解决空白，不是用编造内容填满；警惕 data slop / iconography slop / gradient slop。
- 必须给 variations 不给孤案：跨维度（视觉/交互/色彩/布局）给几个变体，纯视觉并排展示，交互多路由做成可选切换，让用户 mix-and-match（Design-me 内至少提出方向变体供确认）。
- 签名按 SKILL.md「设计与审美双闸门」：全页只留一处，能指认来自本产品的哪一个名词，指认不出就删。
- 必须先对齐假设再动手：开工把 assumptions + reasoning + placeholders 写进产物开头、尽早给用户看，确认方向后再填实；理解错早改比晚改便宜 100 倍。
- 必须反 AI slop：无通用紫渐变、无逐处 emoji 图标、无圆角卡片+左 border accent 滥堆、无 SVG 手画人脸；判断边界「品牌本身用是唯一合法破例」；禁的是「均匀深蓝 `#0D1117`+霓虹 glow」而非一切暗色。
- 必须守住可读性硬底线（任何安静风格不豁免）：正文 ≥14px、标签/注释 ≥12px、正文对比度 ≥4.5:1；留白必须是构图（首屏有视觉锚点），不是内容缺席。
- 必须做信息密度分型：默认克制型（少一层容器/少一个 border/少一个装饰 icon）；但产品核心卖点是 AI 智能/数据可视化/上下文感知（Dashboard、Tracker、Copilot、记账、健康监测类）时走**高密度型**——每屏 ≥3 处**有内容的**差异化信息，装饰性 icon 照样忌讳。加的是有内容的密度，不是装饰；安静派做过头（大片死白+微缩字号）= 第一眼像页面渲染坏了。
- 可交互演示的资产可靠性：交付形态为「双击就能开」的单文件 HTML 时，图片/logo 须 base64 内嵌，相对路径资源挪目录即裂图；交付前用 Playwright 验证无裂图（逐 `<img>` `naturalWidth>0`，或断言 console/request 无资源 404）——**裂图不抛 pageerror，是静默失败**，只查 pageerror 查不出来。

## 6. 内嵌到 Phase 4 高保真的工作纪律

- 4.0 已读低保真布局契约，把「从 existing context 出发」内嵌为硬检查：高保真只「上色+精化」，布局改动先回退 Phase 2，不偷改信息架构。
- 把「placeholder 真诚」内嵌为收敛项：高保真页内**无 emoji 占位 / CSS 色块糊弄**——空状态/引导/错误插画必须用 Phase 4 真实 toapis 图；缺真实数据时标诚实占位并告知「数据待补」，不编造假数字。
- 把「先对齐假设」内嵌到审阅迭代：每屏确认时给变体方向供选择。签名按 SKILL.md 双闸门执行。
- 把「反填充」内嵌到 4.2 视觉档次自检：无 data/icon/gradient slop、无「AI 默认味」堆砌（品牌语义引用 Phase 3 Token），删掉任一元素无所损就删。
- 把「form 推导五问」内嵌为 Phase 4 开工前置：按第 3-4 条逐屏答一遍（UI 版改写），五问答案连同「form 来自内容的哪里」写进产出开头 assumptions 区，答不出第五问不进入 4.2。
- 把「Playwright 验证 + 控制台 pageerror=0 + 交付前肉眼」内嵌为 Phase 4 收敛条件（与 4.2「原型可交互可演示」合并执行）：多 viewport 截图、关键流程点击测试、真实浏览器肉眼过一遍，任一不过不进入 Phase 5。
- 把「5 维度专业评审 + Keep/Fix/Quick Wins、评设计不评设计师」内嵌为高保真审阅迭代的可选质检：方向确认用 5 维度考核，Fix 按 ⚠️致命/⚡重要/💡优化给可执行修复，Quick Wins 给 5 分钟能做的前 3 件。
- 区分职责边界：Phase 4 只做「长什么样」（视觉/交互/品牌），信息架构改动回 Phase 2，视觉基线改动回 Phase 3，Token 是契约、改 Token=改设计，不越层偷改。
